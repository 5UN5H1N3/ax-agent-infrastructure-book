# LLM как вычислительный компонент агентной системы

Для эксплуатации agent infrastructure не требуется выводить формулы attention, но нужно понимать, какие свойства модели определяют latency, стоимость и надёжность системы.

### Tokens, context и generation

Текст перед запросом разбивается tokenizer'ом на токены. Модель получает последовательность токенов контекста и предсказывает следующие. **Context window** - ограниченный бюджет для system instructions, пользовательской цели, истории, результатов tools, retrieved documents и промежуточного состояния. Когда агент «забывает», проблема часто не в memory module, а в том, что нужная информация не попала в текущий context или была выдавлена/сжата.

Generation условно состоит из двух существенно разных стадий. **Prefill** обрабатывает входной контекст и строит KV-cache. **Decode** последовательно генерирует новые токены, многократно обращаясь к KV-cache. Большой context сильнее нагружает prefill и память, а большой объём output - decode. Это важно для планирования concurrency локального inference.

### Tool calling и structured output

Современные API позволяют модели не только вернуть текст, но и выбрать tool и сформировать аргументы по схеме. Это не означает, что tool был выполнен. Ответ модели - лишь **proposal**. Harness должен валидировать имя инструмента, аргументы, полномочия, бюджеты и только затем вызвать внешнюю систему. Поэтому нельзя строить security boundary на фразе «модель обещала вызвать только read-only tool».

Structured output уменьшает синтаксическую неопределённость, но не гарантирует семантическую корректность. Значение `router_id=17` может пройти JSON Schema и всё равно оказаться неправильной целью. Для destructive action нужна проверка объекта, scope и preconditions вне LLM.

### Sampling и детерминизм

Температура и другие sampling parameters влияют на разнообразие генерации, но «temperature=0» не превращает сложную LLM систему в детерминированный автомат: остаются различия серверных реализаций, batching, model revisions, floating-point effects и неоднозначность самого запроса. Поэтому production pipeline должен быть устойчив к тому, что один и тот же logical step иногда даёт разные решения.

### Stateless request против stateful agent

LLM endpoint обычно не является долговременной памятью приложения. Даже если API предлагает conversation/thread abstraction, архитектурно разумно считать модель заменяемым вычислительным сервисом, а authoritative state хранить в собственной системе. Это особенно важно при suspend/resume, смене модели или переходе между cloud и local inference.

### Практическая формула

При проектировании каждого шага разделяйте четыре вещи: **входные данные**, **контекст для модели**, **authoritative state**, **side effect**. Модель может помочь решить, что делать; authoritative state и подтверждение результата должны жить вне неё.
