# Как читать эту книгу и что именно зафиксировано

**Статус:** `СВЕРКА ПО ИСТОЧНИКАМ` · `ФИКСИРОВАННЫЕ ПРОФИЛИ` · `СТЕНД НЕ ИСПЫТАН`

Книга помогает инженеру выбрать и эксплуатировать инфраструктуру для агентов. Сначала разберём, какую задачу решает каждый слой: модель, обвязка агента, инструменты, среда исполнения и оркестратор. Затем свяжем эти слои на примере AX и Agent Substrate и предложим задания для проверки их поведения на вашем стенде. Цель — уметь объяснить выбор инструмента, увидеть границы его гарантий и найти причину сбоя, а не просто повторить установку из README.

### Три маршрута чтения

| Задача читателя | Маршрут | Результат |
| --- | --- | --- |
| Освоить стек с начала | 1–7 → 8–19 → 20–25 → 26–34; затем нужные deep dives 35–43 | Понимание ролей компонентов и причин выбора; лабораторные наблюдения вместо обещаний |
| Собрать учебный стенд | 8–9, 12–19 → 26 → 32; 20–21 для моделей, 23–24 для доступа | Зафиксированный профиль, smoke test, проверка состояния и ограничений. Между 26 и 32 сверить версии заново |
| Диагностировать или готовить эксплуатацию | 25, 29 и 43; 38–40 для state/snapshot/network; 27, 42 и B для восстановления и допуска | Причина отказа, безопасный recovery и доказательство результата, привязанные к вашей сборке |

При первом знакомстве не обязательно читать все углублённые главы подряд. Начните с основного объяснения, затем вернитесь к deep dive, когда нужен конкретный выбор или возник сбой. [34. Mental models, glossary и cheatsheets](34-mental-models-glossary-cheatsheets.md) показывает, какие вопросы уточняет каждый поздний разбор; [приложения](appendix-a-audit.md) помогают проверить источники и готовность системы.

### Практика: код и каталог примеров

Чтобы попробовать первый harness, не нужны AX, Kubernetes, GPU или ключ модели. Начните с программы главы 4: она получает заранее подготовленные ответы и показывает, как обвязка проверяет предложения инструментов. Затем выберите опыт из каталога ниже. У каждого есть собственный предмет проверки; успешный запуск модели поведения не означает, что испытана настоящая платформа.

#### Получить именно код этого учебного среза

Для 39 программ каталога закреплён [срез программ книги 51572b91](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/tree/51572b91c04609b6a234418896bc43fdb64b5bd5/examples). Это commit репозитория книги, а не версия AX или Substrate. Все ссылки «код» и «тест» в каталоге ведут к этому же полному SHA. Редакционная навигация может быть новее кода: повторять эти опыты следует с закреплёнными программами, а не с произвольным будущим main. Отдельный сквозной companion ниже поставляется с более новой редакцией книги и не входит в этот старый срез.

```
git clone https://github.com/5UN5H1N3/ax-agent-infrastructure-book.git
cd ax-agent-infrastructure-book
git switch --detach 51572b91c04609b6a234418896bc43fdb64b5bd5
git rev-parse HEAD
python3 --version
python3 -m venv .venv
. .venv/bin/activate
export PYTHONDONTWRITEBYTECODE=1
python examples/ch04_harness_demo.py
python -m unittest discover -s examples -p 'test_ch04_harness_demo.py' -v
```

Копируйте checkout-команду в новую учебную копию; не переключайте ею рабочий репозиторий с несохранёнными изменениями. Если Git недоступен, скачайте ZIP именно указанного commit через GitHub, распакуйте и перейдите в каталог с README и examples. Сохраните SHA и версию Python рядом с результатом. Все дальнейшие команды этого раздела выполняются из **корня репозитория книги**, с активированным окружением. Не запускайте отдельный файл из случайной папки: некоторые программы импортируют соседние учебные модули.

Проверенное окружение этой редакции: Linux x86\_64, Python 3.13.5, модуль sqlite3; для опыта 40 также OpenSSL CLI 3.5.7. Это проверенная конфигурация, не заявленный минимум и не обещание поддержки любой ОС. Для программ 18 и 43 нужны POSIX-сигналы и группы процессов; для 18, 40 и 43 должно быть разрешено слушать 127.0.0.1 на свободном порту. Все 39 программ обходятся стандартной библиотекой Python; pip install для них не нужен. Git нужен для получения кода, venv — для отдельного окружения. Зависимости сборки книги и ПО инфраструктурных лабораторных сюда не входят.

В первом запуске ожидаются status=completed, evidence.tests.passed=false и source=simulated, затем события repo.read\_file, tests.run, result\_built. Это правильный учебный результат: harness собрал объяснение об известном дефекте. Функция tests.run здесь возвращает fixture, а не запускает тест приложения. Следующая команда действительно запускает авторские проверки harness и должна закончиться OK. Таким образом, «дефект найден», «тест приложения прошёл» и «учебная программа проверена» — три разных утверждения.

#### Как выбрать режим запуска

**Новый сквозной маршрут.** В `examples/learning_harness/` этой редакции находятся ещё две точки запуска: `harness.py` и `evals.py`; их общая проверка — `examples/test_ch04_learning_harness.py`. Это дополнение к 39 программам таблицы, а не незаметная замена их закреплённых версий. Для него возьмите отдельный срез по ссылкам ниже: старый SHA из команды выше не содержит нового каталога. Из корня такой копии выполните `python3 -m examples.learning_harness.harness`, затем `python3 -m examples.learning_harness.evals`. Требуются POSIX, Python и loopback; по умолчанию используются собственный временный файл и HTTP mock, без ключей, GPU и модели. Полный путь обмена разобран в [главе 4](04-agent-harness.md), оценки подготовленных ответов — в [главе 2](02-llm-as-compute.md); тот же код даёт локальный старт Lab 10 в [главе 32](32-labs.md). Флаг `--base-url` companion включает настоящий endpoint только вместе с `--allow-source-upload`; он может передать прочитанный файл и вызвать платную генерацию.

Закреплённый [срез companion 7d927c1a](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/tree/7d927c1a5cdbfe0620cd41f2c27474fd129db8a6/examples/learning_harness), [полный eval-набор](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/blob/7d927c1a5cdbfe0620cd41f2c27474fd129db8a6/examples/learning_harness/cases.json) и [общие тесты](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/blob/7d927c1a5cdbfe0620cd41f2c27474fd129db8a6/examples/test_ch04_learning_harness.py) относятся к одной ревизии. В новой учебной копии репозитория после clone выполните `git switch --detach 7d927c1a5cdbfe0620cd41f2c27474fd129db8a6`, затем команды нового маршрута из корня этой копии. Для примера достаточно стандартной библиотеки; не переключайте существующую рабочую копию с несохранёнными изменениями.

**Первый модельный профиль.** Каталог `examples/model_profile/` продолжает маршрут L01/L02; срезы 51572b91 и 7d927c1a не содержат этого дополнения. Возьмите [закреплённый код L03](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/tree/9072815ae2625165642cda208e694a46b3863ef8/examples/model_profile), [паспорт Qwen3-0.6B](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/blob/9072815ae2625165642cda208e694a46b3863ef8/examples/model_profile/qwen3_06b_profile.json) и [его тесты](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/blob/9072815ae2625165642cda208e694a46b3863ef8/examples/test_ch20_model_profile.py) из одной ревизии. В новой учебной копии репозитория после clone выполните `git switch --detach 9072815ae2625165642cda208e694a46b3863ef8`; не переключайте существующую копию с несохранёнными изменениями. Из корня этой копии запустите `python3 -m examples.model_profile.profile`: он читает карточку без сети и модели. Инструкция `examples/model_profile/README.md` описывает остальные режимы. Флаг `--plan` только печатает команды; загрузка и запуск выполняются читателем отдельно. Флаг `--check` читает локальную поставку, а `--collect-eval` обращается к своему endpoint только с явным разрешением передачи синтетического кода. Заполненная карточка и последовательность допуска разобраны в [главе 20](20-local-inference.md). Дополнение не меняет 39 программ каталога и закреплённый код L01/L02.

Закреплённые срезы каталога 51572b91, L01/L02 7d927c1a и L03 9072815a не содержат этого дополнения. Используйте полную копию книги на commit `70f4878603c740329ad42a7741545e6a4387f79c`: [код и инструкция](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/tree/70f4878603c740329ad42a7741545e6a4387f79c/examples/trace_context), [зависимости](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/blob/70f4878603c740329ad42a7741545e6a4387f79c/examples/trace_context/requirements.txt), [тест](https://github.com/5UN5H1N3/ax-agent-infrastructure-book/blob/70f4878603c740329ad42a7741545e6a4387f79c/examples/trace_context/test_demo.py). #### Три запуска, которым нужна отдельная инструкция

**Глава 5: восстановление после остановки.** На Linux создайте новый каталог и сохраните его имя. Первый процесс намеренно заканчивается с кодом 23 после commit в имитируемом сервисе; это ожидаемая точка сбоя, а не ошибка установки. Второй запуск должен использовать тот же каталог, иначе восстанавливать будет нечего.

```
recovery_dir=$(mktemp -d /tmp/ax-book-recovery.XXXXXX)
python examples/ch05_recovery_demo.py "$recovery_dir" --crash
echo "$?"
# Ожидается 23; продолжайте следующей отдельной командой.
python examples/ch05_recovery_demo.py "$recovery_dir"
```

Итог второго запуска: service\_jobs=1, test\_outcome=failed, simulated=true. Два SQLite-файла остаются в recovery\_dir для осмотра; это не настоящий тест приложения и не Full snapshot. После изучения удалите только созданный учебный каталог обычным способом. Не используйте для опыта базы или каталог другой работы.

**Глава 32: намеренно неисправный проект.** Генератор получает существующий родительский каталог и создаёт новый ax-lab32-batching. Случайный путь к рабочему проекту здесь не нужен.

```
exercise_parent=$(mktemp -d /tmp/ax-book-batching.XXXXXX)
python examples/ch32_batching_exercise.py "$exercise_parent"
python -m unittest discover -s "$exercise_parent/ax-lab32-batching" -v
```

Ожидаются 10 тестов, 3 failures (test\_tail, test\_short, test\_coverage) и exit code 1. Это baseline задания, который нельзя «лечить» ослаблением тестов. Авторский test\_ch32\_batching\_exercise.py, напротив, должен быть зелёным: он проверяет генератор и заданный дефект. Созданные три файла остаются до вашей уборки. Не передавайте агенту весь репозиторий книги с авторским эталонным исправлением. Полный маршрут и integration gate находятся в [главе 32](32-labs.md).

**Глава 20: явное включение HTTP.** Без флагов используется fixture. Для настоящего запроса сначала прочитайте главу 20, поднимите разрешённый учебный сервер и согласуйте расход. В probe нет adapter для авторизации или защищённого получения ключа; не помещайте секрет в URL. Доступ из другой машины должен иметь отдельную проверенную границу.

```
# Только если ваш учебный endpoint уже работает на этой машине:
python examples/ch20_inference_contract.py \
  --base-url http://127.0.0.1:8080/v1 --model review-code --timeout 30
```

Probe проверяет узкий двухходовый non-streaming tool contract, а не качество модели, производительность или доступность из Actor. Имя review-code должно соответствовать model ID вашего сервера. Если ответ не соответствует контракту, разберите отказ; не записывайте его как удачный inference benchmark. Автоматического fallback на внешний сервис здесь нет.

Для фиксации опыта сохраните SHA кода, Python/ОС, точную команду без секретов, exit code, stdout/stderr и собственное объяснение результата. Запись «не запускалось» нужна для непроверенной ветки. Локальный результат сопоставляйте с ожидаемым эффектом из каталога, а не только с нулевым exit code.

### Как обозначены версии

У книги несколько профилей, а не одна универсальная сборка. Номер `v1.0.0` относится к первому выпуску книги; `v0.3.1` и `v0.3.0` ниже относятся к upstream-проектам. Дата MCP является revision спецификации, а SHA фиксирует исходники. Дата редакции в паспорте не означает, что все проекты проверены на их сегодняшнем `main`.

Карта ниже является единой версионной базой издания. Короткая подпись commit содержит восемь символов; ссылка на код раскрывает полный SHA. Для запуска дополнительно фиксируйте digest image, версии CLI/server и конфигурацию. Наличие доступных commits не доказывает совместимость пары.

В AX `v0.3.1` работает отдельный `ax-controller`. В срезе [`ac233282`](https://github.com/google/ax/commit/ac2332829f22360ff97b0ba34d94dd0dd782f17e) очередь Redis Streams и отдельный controller удалены: `ax-server` сам выполняет reconciliation под блокировкой ресурса. Это две реализации, а не два описания одной схемы. В обеих проверенных schema есть `Task`, `Workspace` и `Model`; сетевой gateway Substrate не является четвёртым AX kind.

Короткий SHA здесь служит подписью; ссылка фиксирует полный commit. Общие объяснения в ранних главах не обещают наличия каждого обсуждаемого pattern в AX. Если глава ссылается на движущийся `main`, `master` или `latest`, используйте её для знакомства с механизмом; конкретные поля и команды сверяйте по выбранной schema и сохраняйте полный SHA, image digest и конфигурацию.

Главы 26 и 32 предлагают разные AX-профили поверх development-среза Substrate. Перед переходом между стендами заново зафиксируйте версии CLI и server и повторите smoke test; не объединяйте их результаты в один benchmark. Experimental OpenFGA из главы 24 также нельзя считать свойством Substrate v0.3.0 из позднего аудита.

Метки описывают происхождение утверждения, а не результат испытания стенда:

- **IMPLEMENTED** - механизм найден в коде или официальной документации указанного профиля; это не отметка выполненного integration test.
- **MAIN DELTA** - изменение после релизной базы, рассматриваемое на указанном фиксированном commit. Метка не означает актуальное состояние движущегося `main`.
- **ROADMAP** - объявлено разработчиками как направление, но не должно приниматься за доступную production-функцию.
- **BACKGROUND** - общая инженерная база или рекомендуемый pattern, а не обещание AX.

### Главная оговорка

AX и Substrate - pre-stable системы. AX использует `ax.io/v1alpha1`, а Substrate прямо предупреждает о быстрых breaking changes. Поэтому любые production-планы должны начинаться с pinning версий, проверки совместимости и отдельного test environment. В этой книге команды лабораторных работ являются **шаблонами воспроизводимого стенда**, но перед применением в реальной инфраструктуре необходимо сверять release notes выбранных версий.

### Что книга намеренно не делает

Она не заменяет полноценный курс Kubernetes, не погружается в математику Transformer'ов и не проводит построчный аудит Go-кода. Если механизм можно понять и эксплуатировать, не разбирая конкретную реализацию до функции и struct, мы остаёмся на архитектурном уровне. И наоборот: runner, жизненный цикл, snapshots, сетевые шлюзы и границы доверия разбираются глубоко, потому что ошибки именно здесь дают эксплуатационные и security-инциденты.
